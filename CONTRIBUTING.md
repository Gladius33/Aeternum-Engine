# Contributing

Open an issue for substantial changes. Keep changes small, domain-focused and tested.
Use PHP 8.4, strict types, English identifiers and documentation. Run `php tests/run.php` and lint all PHP files before opening a PR. Preserve deterministic execution and world isolation. Do not commit secrets, runtime data, generated dependencies or personal data. Maintain .gitignore, ROADMAP.md, CHANGELOG.md and docs/ as applicable.

External contributions require explicit acceptance of [CLA.md](CLA.md) before merge. The maintainer records acceptance for the applicable PR and verifies employer authorization where necessary; an automated check is not a substitute for that review. Do not submit third-party code unless its license is identified and compatible.

Use pull requests; do not merge failing or unverified CI checks. Report security issues privately as described in SECURITY.md.
