# M12 — security/resilience/capacity qualification (IN PROGRESS)

## First real increment
- JSON-only response policy uses immutable reusable headers for all API routes,
  including exceptions and plaintext rejection.
- Negative loopback HTTP tests exercise cleartext denial on multiple endpoints,
  no HSTS without trusted TLS, no-store, nosniff and strict JSON CSP/CORP.
- Unit regression covers safe header names/values and TLS policy.
- Separate CI checks pinned npm dependencies including development toolchain.

## Second security hardening increment
- StrictJson validates UTF-8, JSON syntax and depth using the native PHP parser,
  then performs a bounded second lexical pass rejecting duplicate keys even when
  the duplicate has a different Unicode escape spelling.
- Public auth, social, economy payloads and trusted pack/world manifests share
  the same fail-closed parser. Existing API error responses remain 400 invalid_json.
- Regression covers nested objects, escaped braces, generated duplicate corpus,
  rejected ambiguous pack identity and a real MariaDB-auth HTTP negative case.

## Deterministic JSON property/fuzz coverage (CI pending)
- Run `php tests/m12-json-fuzz.php`; fixed PRNG seed `0x12A37E`, no network,
  database, external fuzzer or dependency installation.
- 512 generated valid documents must decode identically to native PHP in both
  object and associative modes.
- 1,024 Unicode/escape-equivalent duplicate object keys must be rejected;
  1,024 sibling-object controls with identical names must remain valid.
- 13 malformed or excessive-depth inputs and a long escaped string exercise
  native grammar and lexical boundary handling.
- CI executes this harness separately. This is bounded deterministic fuzzing,
  **not** a claim of exhaustive parser testing, concurrency qualification,
  penetration testing or M12 release readiness.

## Player-facing social input hardening (CI pending)
- Alliance creation rejects malformed UTF-8, C0/DEL control characters,
  and Unicode bidi embedding/override/isolate controls. Ordinary accented
  names remain accepted by the validation policy.
- MariaDB-integrated HTTP/model regressions verify rejection before a name
  can be persisted. This does not replace a complete output-encoding/XSS
  audit of every web client rendering context.

## Bounded disposable MariaDB read-capacity baseline
- Repeat 100 authorized paginated market reads and 100 authorized stock reads
  over M03's actual 1001-offer, 1002-resource database fixture.

  but is **not** a production latency SLA or maximum concurrent user claim.
